# Implementation Plan: TLD Batch Sync & API Routes

**Branch**: `015-tld-batch-sync` | **Date**: 2026-07-30 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/015-tld-batch-sync/spec.md`

## Summary

Add a server-side batch sync job processor that checks TLD reservation status across all portfolio domains (Phase 17), plus API routes for job management, single-domain refresh, and extension data lookup (Phase 18). The sync engine processes domains in small groups with incremental persistence, split DNS queries across Cloudflare/Google, supports resumption after interruption, and delivers live progress updates to the client.

**Technical approach**: Sync jobs live in the `tld_check_jobs` table. A Route Handler processes the job in chunks (5 domains at a time), calling Phase 16's engine per domain group. Progress is streamed via Supabase Realtime (with polling fallback). API routes follow the existing Sedo/Spaceship route pattern: authenticate via Supabase server client, validate domain ownership, proxy to engine functions.

## Technical Context

**Language/Version**: TypeScript 5.x strict mode

**Primary Dependencies**: Next.js 14+ App Router, Supabase (database + auth + realtime), Cloudflare/Google DoH

**Storage**: Supabase PostgreSQL — `tld_check_jobs` (job tracking), `domain_extension_checks` (results), `tld_extensions` (TLD list), `domains.reserved_tlds_count` (summary). RLS on all tables.

**Testing**: Manual verification + `npx tsc --noEmit` + API route testing via HTTP client

**Target Platform**: Vercel (serverless functions) + Supabase Edge Functions (for long-running syncs if needed)

**Project Type**: Web application — Next.js App Router with Route Handlers

**Performance Goals**: 50 domains × 10 TLDs (500 pairs) within 5 minutes; progress updates every 3s; single-domain refresh under 20s

**Constraints**: Vercel serverless function timeout (10s–60s). Chunked processing with DB-backed state for resumed execution. One active job per user.

**Scale/Scope**: ~4 API routes, 1 job processor module, 1 progress subscription hook, UI integration points on domains page. No new database tables (Phase 14 prerequisite).
