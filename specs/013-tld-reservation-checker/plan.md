# Implementation Plan: TLD Reservation Checker

**Branch**: `013-tld-reservation-checker` | **Date**: 2026-07-30 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/013-tld-reservation-checker/spec.md`

## Summary

Add a TLD Reservation Checker tool that lets users enter base words, select TLDs, and check domain availability across those TLDs. Results show Available/Registered/Reserved/Error status in a table with filtering, CSV export, and terminal-style UI matching the DNS Checker.

**Technical approach**: DNS-based NS record heuristic via Cloudflare/Google DoH — mirrors the existing DNS Checker's `lib/dns/` architecture exactly. A domain returning NS records is "Registered"; a domain returning NXDOMAIN is "Available". This requires zero new server infrastructure, no API keys, and works entirely client-side.

## Technical Context

**Language/Version**: TypeScript 5.x strict mode

**Primary Dependencies**: Next.js 14+ App Router, React 18, TanStack Query v5, shadcn/ui, Lucide React, Tailwind CSS v3

**Storage**: Browser session storage (TLD selection persistence). No database changes.

**Testing**: Manual verification + `npx tsc --noEmit` type checking

**Target Platform**: Web (Vercel deployment), browsers with `fetch()` support

**Project Type**: Web application — single Next.js app with App Router

**Performance Goals**: 50 combinations (5 words × 10 TLDs) resolved in ≤ 30 seconds; CSV export ≤ 100ms; filter updates ≤ 200ms

**Constraints**: 20 concurrent lookups; 5-second timeout per lookup; max 200 base words

**Scale/Scope**: Single page tool; ~10 new components; ~3 new lib files; 2 nav edits
